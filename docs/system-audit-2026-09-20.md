本轮在 `Astra_920` 的现有工作区上完成，源码版本保持 `7.3.0`。保留当前页面结构、业务流程和已有设计，重点修复数据一致性、并发与异步边界、分页统计、导入导出和实际显示问题。

开始前工作区已有较多未提交修改，已记录 [起始状态](../output/system-audit-20260920/starting-status.txt) 和 [起始补丁](../output/system-audit-20260920/starting-worktree.patch)。本报告只描述本轮新增的审查与修复，不把之前的品牌、配色、样机预约等改动冒充为本轮成果。本轮没有提交、推送、发布或修改版本号。

## 已修复的主要问题

| 范围 | 触发条件与修复后的行为 |
| --- | --- |
| 数据写入边界 | 修复样机循环变量覆盖请求载荷；阶段排序只修改同项目阶段顺序；拒绝无关任务修改与非法归属后不留下写入副作用。项目、阶段、样机、样机池支持 revision 冲突校验。 |
| 样机身份与占用 | 在写事务内检查 SN、IMEI、板号的交叉重复；批量插入也不能绕过检查。结束、删除、销毁时按全部有效预约重算占用；销毁不能顺带新增预约或修改无关任务。 |
| 分页、搜索与统计 | 修复 SKU 0、深度关键词、直接字段与历史字段联合搜索；归档任务从工作区和摘要隐藏，仍保留履历与导出。人员数量与筛选项来自完整服务端数据。阶段样机台次与占用数量覆盖全部任务，不依赖前端已经加载的页数。 |
| 异步保存与旧响应 | 增量保存按顺序发送并使用发送时 revision；409 后旧请求、旧回滚快照不能覆盖重载数据。详情合并等待在途保存结算，校验读取版本并有限重读，覆盖“旧详情先到”和“保存确认先到”两种顺序。失败草稿不会被详情或导入水合误覆盖、误确认。分页、照片、履历和导入预览的延迟响应不能覆盖新页面或新弹窗。 |
| 弹窗与结果录入 | 防止重复提交；旧异步回调不能关闭后开的弹窗；取消、关闭和 Escape 经过统一取消逻辑。补齐仅修改结果照片、问题来源等变更的识别。人员字段保留未修改的历史值，避免人员停用后无法保存其它字段。 |
| 照片与数据库事务 | 文件创建采用独占写入；失败后清理未引用文件，删除在事务结算后检查引用。覆盖回滚、手动提交后异常、断开响应、嵌套事务、路径别名和模块重复导入。已提交照片不会因响应整理失败而被异常清理误删。 |
| 数据包合同 | 严格验证 ZIP 路径、重复项、manifest、域结构与归属；显式空选择不会变成全量导出/导入。选择范围变化后冲突 ID 保持稳定；样机、任务结果及照片引用跟随实际 ID 映射。 |
| 导入语义 | 修复同库 V2 自导出再导入时注入旧格式默认字段造成的假冲突；保留 false、0、空数组等真实差异。跳过占用时同步移除导入任务关联；事件同 ID 不同内容可保留且重复导入幂等。批量档案提交逐项重新预览。 |
| 导出竞争 | ZIP 写入时核验资产的长度和 SHA-256。导出过程中照片被删除或修改时明确失败并提示重试，清理不完整 ZIP；历史上本就缺失的文件仍按缺失记录呈现。 |
| CSV / XLSX | CSV 支持 BOM、引号内换行、转义双引号与 CRLF，并拒绝未闭合引号；只为有效行占用重复 ID。XLSX 检查 ZIP 边界、CRC、解压尺寸，通过关系定位首工作表，处理 1904 日期系统、公式缓存及非法单元格引用。 |
| HTTP / 运行时 | 拒绝重复、非法和截断的 Content-Length 及不支持的分块请求；JSON mutation 请求必须是对象。路由分段后只解码一次。多次 SELECT 共享读取快照；自有连接及时关闭，借用连接保留所有权。旧 SQLite/WAL 数据迁移改用一致性备份快照；服务停止关闭监听 socket。 |
| UI 显示与操作 | 修复窄屏首页、阶段卡、结果录入弹窗的溢出和过窄列；768px 默认样机池提示恢复可读布局。导入 checkbox/radio 不再被全局 input 样式拉满宽度，窄屏选择树与比较区改为单列。冲突中的对象显示可滚动的完整 JSON，长备注换行，false/0/空值不再混淆。新增卡片可通过键盘操作，侧栏按钮状态及存储失败降级得到修正。 |

### 规模与并发

[规模测试](../output/system-audit-20260920/backend-performance.json) 使用 20 项目、10 万任务、7 万样机、70 万照片元数据。该本机临时库测量中，bootstrap median 57.48ms、项目摘要 7.93ms、任务默认分页 5.11ms。完整规模测量发生在追加阶段样机统计之前，追加部分另测如下；数值代表本次环境，不是对所有部署的延迟承诺。

[阶段样机统计](../output/system-audit-20260920/stage-sample-count-performance.json) 使用 10 万任务、30 万关联，目标 5 阶段聚合 median 11.97ms；查询计划使用索引。

真实 HTTP 混合并发涵盖分页、摘要、照片上传删除、导出、导入预览与提交。[最终混合记录](../output/system-audit-20260920/http-concurrency-transfer-final.json) 中，60 次读取、6 次照片操作、2 次导入均成功；72 次混合操作有 1 次导出因照片同时变化而明确中止。没有把该次失败隐藏为通过；另有真实 HTTP 回归证明中止后重试可成功，输出包逐资产校验通过。

## 明确保留的边界

- 当前分支不包含历史固定 IPv4 ACL 实现。4 组 ACL 独立测试引用缺失模块，仍失败；导入冲突脚本中的历史 ACL 部分明确跳过，86 条业务断言通过。本轮没有引入另一分支的整套权限与交互设计，不能据本轮结果宣称 ACL 已验证。
- 旧工作区视觉测试曾固定要求过时的五行阶段卡、260px 选择框和颜色。按当前认可界面更新语义断言，并以四种宽度的实际截图检查布局，不为旧断言恢复旧界面。
- `.github/workflows/sync-shared-release.yml` 仍读取不存在的 `VERSION` 并限定 7.2 系列，与当前 7.3.0 源码不一致。下一次正式发布前需要确定并更新 7.3 发布工作流；本轮没有执行发布或改变远程 tag。
- 本机 `.git/info/exclude` 忽略 `dev/` 与 `AGENTS.md`，其中测试适配和代码定位图更新目前只存在于工作区。新增的 `tests/` 回归与本报告是可纳入后续提交的文件。提交时应单独审查本轮内容与开始前已有改动。

详细修复与独立反例记录见 [后端审计摘要](../output/system-audit-20260920/backend-findings.md) 和 [前端审计摘要](../output/system-audit-20260920/frontend-findings.md)。新增后端回归的公共 fixture 位于 `tests/backend_fixture.py`，不依赖被忽略的 `dev/` 目录。

以上验证覆盖了已列出的路径与边界，并不构成不存在其它缺陷的保证。已知阻断、历史不适用测试和并发中止均按实际结果保留记录。

# 样机预约与实际执行

任务的 `sampleIds` 同时保存计划预约和实际使用关系，不新增第二份预约数据。共享规则位于 `backend/server_modules/task_reservations.py`，候选查询、任务保存、整包导入和完整状态保存共用该规则。

- 计划区间沿用日期字段，包含开始日与结束日。同日相接仍算重叠，次日起可复用。
- 同一样机可预约给计划区间不重叠的多个任务，支持跨阶段、跨项目。任何一方未填写完整有效的时间，不能据此放行共享。
- 进行中和阻塞中的任务都持有实际使用权。两个实际执行任务不可共享样机，即使计划日期已经过去；必须先结束或移除样机，才能启动下一个任务。
- 取走分析、已退库保持不可用。已有预约不代表启动时仍可用，启动与恢复会重新检查当前样机状态。
- 候选列表采用弹窗中的日期草稿；切换到样机配置或修改临时变更日期时重新查询。日期改变导致已选样机冲突时，显示原因并允许取消选择，服务器在保存时再次校验。
- 预约操作只修改任务与预约履历，不能覆盖样机档案、当前测试任务或实物去向。服务器在同一 SQLite 写事务中确定样机状态：进行中优先，阻塞中其次，再按计划开始日与任务 ID 选择下一预约；最后一个预约移除后恢复闲置。
- 任务结束选定的取走分析或退库去向优先保留，其余预约继续存在，但启动会被拦截，直到样机恢复可用。
- 改期、分配、移除、结束和删除后的状态由服务器查询全部关联任务确定，不依赖前端当前加载了哪些项目或分页。

回归入口：`tests/test_sample_reservations.py`、`tests/frontend_sample_reservations.test.cjs`。后端测试使用项目内独立临时目录，覆盖日期边界、并发预约、跨项目共享、状态交接、不可用状态、导入一致性和失败原子性。

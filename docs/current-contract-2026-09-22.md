# 现行协议与历史兼容清理

本轮按明确要求移除历史接口及其转换代码。保留当前 UI、增量业务操作、分页加载、设备仓库、照片/附件与 V2 数据包功能。没有修改版本号、提交或推送，也没有重启正式服务。

## 已删除的路径

| 删除项 | 当前唯一入口 |
| --- | --- |
| `GET/PUT /api/state`，前端 `save/scheduleSave/reloadFromServer/fullStateUrl` | bootstrap、实体详情、分页 API 和增量 mutation |
| 全状态保存、三方合并、compact 全状态补回照片/事件 | 带 revision 的实体事务；V2 导入使用专用导入事务 |
| V1 `state.json` 数据包、旧项目默认字段补齐、按旧资产目录猜路径 | ChamberData V2 的域文档、资产索引与校验 |
| 同级旧目录自动复制、迁移报告、`--no-migrate-legacy-data` | 显式数据根或项目内 `data/` |
| SQLite 补列、历史状态/身份/任务关联回填、内嵌状态自动外置 | 新库直接创建现行 schema；旧结构在写入前拒绝 |
| 旧状态别名、日志与备注递归改词、旧人员字段拆分、旧退出记录转换 | 当前枚举与结构化记录；自由文本原样保存 |
| 内嵌 data URL 照片写入、缩略图重复别名、旧问题字段派生 | multipart 照片上传、`thumbUrl`、`problemRecords` |
| 旧 CSV 单行包装、旧人员单列模板、旧“方案”列回退 | 当前 CSV 解析器和模板字段 |
| 依靠任务名称猜问题归属、旧脏文本过滤、未知任务动作通行 | 按 taskId 归属，状态转换使用明确业务动作 |

完整删除四个运行模块：`state_merge.py`、`state_persistence.py`、`database_backfills.py`、`import_defaults.py`。照片写入后的 revision/审计事务迁入 `sample_asset_mutations.py`，保留文件事务与回滚保护。

与本轮开始时的工作树快照相比，运行源码新增 296 行、删除 2249 行，净减少 1953 行；未改变 HTML/CSS。此统计不含测试、文档和上一轮模块拆分。

## 仍然存在的业务机制

- 服务内部 `get_state/compose_state/split_state_for_storage` 用于 V2 导入导出和外置表存储投影，不提供 HTTP 全量写入。
- `_baseData` 仍用于未保存编辑保护、局部确认与失败回滚；它不再发送给三方合并服务。
- 跨平台样机履历、历史结果快照、问题来源和不可变日期属于当前业务数据，继续保留。
- 不同实体的字段裁剪、revision 冲突、照片归属、损坏文件拒绝和重复身份检查属于当前数据完整性规则，继续保留。
- 当前数据中可能留存不再读取的历史 JSON 扩展字段。本次不批量清洗正式数据库；删除兼容代码不等于删除业务记录。

## 输入和部署约定

旧 API 不再可用：GET `/api/state` 返回 404；服务器不实现 PUT，返回 501。旧 V1 包、旧状态枚举和内嵌照片不再转换。旧数据库缺少现行外置表/查询列或仍保存内嵌全量状态时，启动报错，不自动补列、回填或迁移目录。

启动只指定当前数据目录：

```powershell
python -m backend.server --host 127.0.0.1 --port 9398
```

扩展现行协议时，同步修改服务、前端调用、V2 数据包合同及回归测试；不要重新添加旧接口回退。当前维护导航见 [architecture.md](architecture.md) 与 [maintenance.md](maintenance.md)。

## 追加核查：残留数据兼容分支

- 移除问题任务标签的旧三段格式自动补方案逻辑。现行记录在创建时写入完整标签；显示时使用保存的来源快照，不推测或重写历史文本。
- 移除“既有重复身份仍可编辑”的豁免。每次提交的非重组样机均按现行唯一性规则检查；重复身份返回冲突且事务不写入。重组样机允许重复属于现行业务规则，保持不变。
- 移除问题图片关联的历史放行分支。样机问题、任务草稿与结果中的关联都必须指向属于该样机的有效照片；已有失效引用同样拒绝。
- 保留文件清理中的路径归一化与引用保护，避免别名指向同一文件时误删仍在使用的资产；这属于删除安全边界，不提供旧 API 或数据迁移。

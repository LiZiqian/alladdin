# 开发、验证与交接指南

## 接手时先做什么

1. 阅读 [架构导航](architecture.md)，确认当前 Git 分支及 `git status --short`。本次整理基于已有大量未提交改动的工作树，不要用旧提交覆盖当前实现。
2. 安装项目支持的 Python 与用于开发检查的 Node.js。运行不需要 Node.js，也没有 pip/npm 依赖。Windows 本机如有项目环境绑定，优先使用明确的解释器路径。
3. 运行 `python scripts/check.py`，在 `output/checks/results.json` 和每套 `.log` 中检查结果。脚本失败会返回非零退出码。
4. 开发预览使用独立数据目录，确认界面后再评估真实数据部署。

```powershell
python -m backend.server --host 127.0.0.1 --port 9490 --data-dir output/dev-data
```

`--data-dir` 必须位于项目内部。不要让开发验证指向正式 `data/`，不要删除正在使用的 SQLite WAL 文件。日常测试使用内存库或自身的临时目录；检查脚本清除继承的 `TESTCHAMBER_DATA_DIR`，防止部署环境配置干扰测试。

## 新增或修改功能

### 业务字段与接口

1. 确认字段属于哪个实体、是否外置、是否派生、是否参与查询索引。
2. 在对应校验/服务/record writer 修改后端。持久化字段变化时核对 schema 合同、导入导出和现行字段校验。
3. 在 `server/api.js` 或相应 mutation 模块添加通信逻辑；业务页面不自行保存全状态。
4. 更新对应详情/表单，再补成功、拒绝、陈旧版本和跨实体影响的回归。

### 新前端模块

1. 用唯一模块名注册，避免覆盖已存在的方法名。
2. 加到 `frontend/index.html` 的恰当位置，必须在 `app.init()` 前加载，保留版本占位符。
3. 新模块保持注册时无网络/业务副作用，真正初始化在 `app.init()` 或用户操作时发生。
4. 运行生产模块加载合同测试，确认没有漏载、重复载入或成员覆盖。单元测试需要某组模块时使用 `tests/frontend_source.cjs`，它从实际 index 读取加载顺序。

### 修改 UI

保留既有状态访问器、`data-app-action`、弹窗异步确认约定。修改布局才触碰 CSS；纯架构重构应尽量让页面模板和 CSS 保持原样。视觉验证使用相同数据、相同实际视口和同一交互步骤；截图尺寸不同不能直接做像素差异结论。

## 注释规则

- 文件头说明职责、输入来源及不负责什么；公共入口说明成功/失败返回和事务所有权。
- 对版本屏障、回滚、派生数据、协议拒绝规则和销毁清理写“为什么”，不要逐行复述赋值。
- 一条注释如果声明某种保证，应有对应实现或回归支撑；改代码时同时核对注释。
- 文档导航优先指向稳定的文件和函数名，避免到处复制容易失效的行号。

## 验证与交付

```powershell
# 当前可交付源码与回归
python scripts/check.py

# 单个领域（仍做源码语法检查）
python scripts/check.py --match reservations --output output/checks-reservations
```

每套 Python/Node 测试单独进程运行，避免测试对服务器全局路径、连接或浏览器替身的修改泄漏到下一套。新增测试应放在 `tests/`，不要只放进被本机忽略的 `dev/`。

准备交接时逐项确认：

- 当前 `tests/` 全部通过；旧协议测试应改为拒绝断言，现行业务回归不得因为接口清理而跳过。
- 重要页面能实际加载，核心编辑操作能保存并重新读取。记录具体数据、场景和视口，不泛称“所有情况验证完成”。
- 源码交付包含新模块、`frontend/index.html`、`tests/`、`scripts/` 和 `docs/`；遗漏新脚本会让 UI 部分失效。
- 本机 `.git/info/exclude` 还忽略了 `.gitignore` 本身：本轮新增的产物忽略规则已经在本地生效，但普通 Git 状态不会列出这个文件。准备正式交付时需显式审阅并纳入 `.gitignore`，不能以为规则已随提交共享。本轮没有暂存文件或改写本机 exclude。
- `git diff --check` 通过。不要包含数据库、照片、测试数据、`output/`、浏览器状态、`__pycache__`。
- 发布前再核对版本、资源缓存、发布 workflow、备份和回滚办法。未经明确安排，不将维护重构自动提交、推送或发布。

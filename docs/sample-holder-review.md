# 样机持有人与任务关系核查

核查日期：2026-09-21。依据当前源码与隔离测试，未修改生产样机记录。

## 字段含义

| 字段 | 归属与含义 |
| --- | --- |
| `sample.owner` | 样机档案的挂账人 |
| `sample.borrower` | 样机档案的当前持有人；取走分析时表示取走人 |
| `sample.borrowDate` | 取走分析日期；清空取走人时同步清空 |
| `task.owner` | 测试任务执行人，与挂账人和取走人独立 |
| `resultUploads[].samples[].receiver` | 某次任务结果记录的取走人快照 |
| `currentTaskId/currentProjectId/currentStageId` | 样机当前任务关系，取走分析或退库后释放 |

样机池筛选和项目人员持有数量统计读取同一个 `sample.borrower` 字段。修改当前档案不改写历史结果的取走人快照，也不改变任务执行人。

## 各入口的行为

| 操作 | 持有人与任务关系 |
| --- | --- |
| 新增/调整未来任务预约 | 保留当前持有人、位置与挂账人；服务端防止预约载荷覆盖实际使用信息 |
| 启动、恢复或阻塞任务 | 清空此前的外借人和取走日期，保留挂账人；执行人不自动写入取走人 |
| 保存结果草稿 | 保存任务草稿，不修改当前档案的取走人 |
| 结束任务，去向为取走分析 | 取走人必须选择项目开发人员；写入档案持有人与结果日期，释放当前任务关系 |
| 结束任务，去向为闲置或已退库 | 清空外借人和取走日期；保留/应用表单中的挂账人 |
| 编辑样机档案 | 保留表单明确填写的持有人；无项目上下文时校验姓名/工号，有项目上下文时按开发人员校验；未改动的历史人员允许保留 |
| 修改取走分析中的持有人 | 更换取走人更新日期，清空人员清空日期；只改位置保留已有日期 |
| 归档已完成任务 | 保留任务结束时确定的样机去向与取走人 |
| 旧任务追加结果，或结束含已移除样机的旧任务 | 样机已进入其他未完成任务时，锁定当前档案；服务端拒绝越过锁定的写入 |

样机档案的“持有人”还允许直接登记保管人，因此直接编辑档案与任务流程清理外借人的语义不同。现在不论是否同时修改状态，直接编辑都会保留明确填写的人员；非取走分析状态不记录取走日期。

## 本次修复

1. 档案原先“状态不变”直接写人员，“状态改变”走任务状态函数，导致同一持有人输入随状态是否改变而产生不同保存结果。现在统一通过状态函数，并明确区分档案持有人与任务去向接收人；同时同步取走日期和变更日志。
2. 复现了样机从任务 A 移除、转入任务 B 后，结束 A 仍能覆盖状态和取走人的问题。前端锁定已移除且进入其他任务的样机，服务端在事务内独立检查并拒绝覆盖。分页未加载另一任务时，前端同时参考样机当前任务标识。
3. 问题表移到独立页签，使用真实表格；记录 ID、关联任务及其他原始元数据继续保留。切换页签不提交数据，仍由弹窗确认统一保存。
